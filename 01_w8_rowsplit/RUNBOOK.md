# Как подать это, если ты видишь папку впервые

Три вещи, которых нет в скрипте и без которых он упадёт непонятной ошибкой.

## 0. Что нужно иметь до начала

1. **`gh` авторизован под аккаунтом `MichaelDementii`.** Скрипт пушит в
   `MichaelDementii/ninfer` и открывает PR как `--head MichaelDementii:...`. Если `gh auth status`
   показывает другой аккаунт, `push` упадёт с 403 без внятного текста.
   Форк `MichaelDementii/ninfer` должен существовать — он уже есть.
2. **`gh`, `git` в PATH.** `ssh`/`scp` нужны **только** для стадии `bundle`, которую можно и нужно
   пропустить, см. пункт 2 ниже.
3. Python 3.10+.

## 1. Порядок

```
python make_pr.py check          # ничего не пишет; покажет одну ожидаемую проблему, см. §3
python make_pr.py issue --yes    # открывает Issue, пишет ISSUE_URL.txt
```

**Дальше стоп.** `CONTRIBUTING.md` требует подтверждённый Issue до PR, и `create` без этого
откажется. Ждём его ответа.

Когда ответил:

```
# 1) впиши согласованный объём в PR_BODY.md, строка 3, вместо многоточия
# 2) сохрани его ответ в ISSUE_CONFIRMED.txt (создай файл, текст свободный)
# 3) замени #ISSUE в PR_BODY.md на реальный номер

python make_pr.py fetch --yes    # импортирует branch.bundle в ./work
python make_pr.py push  --yes    # пушит ветку в форк
python make_pr.py create --yes   # открывает PR
```

## 2. Стадию `bundle` пропускай

`branch.bundle` в этой папке — **тот самый коммит, на котором сняты все числа**,
`beced522a7c941e453ee508f4a6ab587e66186c3`. Стадия `bundle` заново тянет ветку с билд-сервера, а
там идёт другая работа и ветка может уехать. Скрипт теперь проверяет голову бандла против
`EXPECT_COMMIT` и откажется, если она не та — но проще просто не запускать эту стадию.

`fetch` работает с закоммиченным бандлом и сервер не трогает.

Если всё же понадобится: ключ к серверу — файл `vast_47972656` в корне проекта (**не** в этой
папке), путь задаётся переменной `NINFER_KEY`, реквизиты в `СЕРВЕР_доступ.md` там же.

## 3. `check` вернёт код 1, и это нормально

Пока в `PR_BODY.md` строка 3 содержит многоточие вместо согласованного объёма, `check` считает это
проблемой и выходит с ненулевым кодом. Так и задумано: `create` тоже откажется. После пункта 1
выше `check` станет чистым.

## 4. Что уже решено, а что нет

**Решено, не переоткрывать:**

- подаём **Issue первым**, PR только после его ответа — правило записано в `CONTRIBUTING.md`
  после закрытия #96;
- одна заявка = один механизм; W8-половина и MoE-половина разделены сознательно, MoE уже влита
  как #106;
- база — `master` (`3a61ef3f`), не `dev`; на момент подготовки они совпадают;
- заголовок обещает **x1.09**, а не x1.12: x1.12 — медиана по формам, которых модель не исполняет,
  и тело это прямо говорит.

**Открыто, решает он:**

- обновлять ли `docs/performance.md` — вопрос 2 в Issue;
- нужен ли ему профиль на умолчательном чанке 1024 (сейчас вся атрибуция `nsys` на 8192);
- захочет ли он увидеть сами численные стенды — они throwaway, в PR не входят, лежат на сервере
  в `/root/scratch_rev2/`.
