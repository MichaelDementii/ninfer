# Блокер кандидата 2 снят: `red.global.add` есть на sm_120a во всех нужных формах

Кандидат 2 («слить финализацию top-8 в эпилог down-GEMM MoE») стоял с пометкой:

> **Блокер, который снимается за час:** нет пробы, что `red.global.add.f32` вообще существует на
> `sm_120a`. Это первое, что надо сделать по этому кандидату — до всякого кода.

Проба сделана. **Существуют все шесть форм, включая векторные.**

Стенд: `90_harness/isaprobe_red.cu`, `nvcc -arch=sm_120a`, RTX 5090, CUDA 13.1.115.
Приёмка двойная — ptxas выходит с нулём **и** опкод виден в SASS (`cuobjdump -sass`), плюс
ядра реально исполняются и меняют память (`run=no error  h=[192.26 160.258 96 128]`).

| PTX | SASS на sm_120a |
|---|---|
| `red.global.add.f32` | `REDG.E.ADD.F32.FTZ.RN.STRONG.GPU` |
| `red.global.add.v2.f32` | `REDG.E.ADD.F32x2.FTZ.RN.STRONG.GPU` |
| `red.global.add.v4.f32` | **`REDG.E.ADD.F32x4.FTZ.RN.STRONG.GPU`** |
| `red.global.add.noftz.bf16x2` | `REDG.E.ADD.BF16x2.RN.STRONG.GPU` |
| `red.global.add.noftz.v2.bf16x2` | `REDG.E.ADD.BF16x4.RN.STRONG.GPU` |
| `red.release.gpu.global.add.f32` | `REDG.E.ADD.F32.FTZ.RN.STRONG.GPU` |

**Лучше, чем требовалось.** Кандидат просил скалярную форму, а есть `F32x4` и `BF16x4` — то есть
шестнадцать байт редукции одной инструкцией. Это ровно то, на чём построен
`epilogue_moe_finalize` у NVIDIA (`sm90_visitor_scatter.hpp:210-215`,
`copy_red_global.hpp:302-317`): вес маршрута и `red.global.add` в эпилоге, без отдельного ядра
редукции.

## Что это НЕ означает

Проба говорит только, что механизм есть. **Приз кандидата ею не подтверждён**, и по нашим
собственным замерам на 35B он, скорее всего, заметно меньше заявленного:

* ядро `sparse_moe_prefill_reduce_kernel` — **1.54% префилла**;
* абляция эпилога у `q4_gate_up` (снята только глобальная запись, остальное цело) дала
  **−1.3%** времени ядра. То есть записи в этом семействе **хорошо перекрыты** и стоят мало;
* по арифметике трафика круговорот `down → grouped_io → reduce` — это ≈268 МБ на срез,
  85.8 ГБ за префилл, что при 1000 ГБ/с дало бы 4.8% префилла. **Расхождение с абляцией в три
  раза, и разрешать его надо замером, а не выбором удобного числа.**

Причина расхождения понятна из круга абляций: маршрутизируемые MoE-ядра **не упираются в трафик**
(снятие всего глобального чтения активаций даёт −5.0%, кодов −4.4%). Арифметика «байты / полоса»
для них завышает цену любой правки по памяти.

## Порядок работ по кандидату 2

1. ✅ Проба ISA — сделана, зелёная.
2. Измерить **цену круговорота** прямо: абляция записи в эпилоге `qx_down` плюс отключение
   `reduce_kernel` (результат неверен, прибор верен). Это даёт потолок кандидата на нашей модели.
3. Только если потолок оправдывает — писать эпилог с `red.global.add`.
4. ⚠️ Побитовость теряется: порядок суммирования восьми путей становится недетерминированным.
   У кандидата есть побитово-безопасный вариант вдвое слабее; на нашей модели «вдвое слабее»
   от небольшого числа может оказаться шумом.
